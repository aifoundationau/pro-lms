======================================================================
1. WHAT THE COMMAND DOES
======================================================================

    firebase deploy --only firestore:rules

- "firebase deploy" uploads things from this folder to your live Firebase project.
- "--only firestore:rules" limits it to ONE thing: the security rules file
  (firestore.rules). Nothing else is touched — no website files, no database
  data, no functions, no indexes.
- Security rules decide who may read or write each part of the database.
  They are enforced by Google's servers, so they cannot be bypassed from the
  browser.

IMPORTANT: Deploying REPLACES the live rules completely with the contents of
firestore.rules. If anyone has edited rules directly in the Firebase Console
since this file was last updated, those console edits will be overwritten.

    ✔  firestore: released rules firestore.rules to cloud.firestore

9. 2026-10-13 RULES UPDATE — WHAT CHANGED AND WHY
======================================================================

New features need these rules before they work for real users:

  /chat_interactions      Message board. Anyone -> Super Admin; teachers ->
                          anyone (the app limits them to their students);
                          students -> teachers of courses they are enrolled
                          in. Messages can be marked read, never edited or
                          deleted. Only the Super Admin sends "Token Grant".
  /course_members         Course rosters (id = <courseId>__<email>). Only the
                          course owner (or Super Admin) enrols; students can
                          read only their own enrolments.
  /lms_coursework         Assessment submissions. Enrolled students submit
                          and resubmit until graded; they can only read
                          their own. Teachers/staff read and grade.
  /course_copies          Global Search copies: who copied which course and
                          when. Immutable.
  /teacher_applications   Applicants write only their own (status pending);
                          only the Super Admin reads all and approves.
  /token_transactions,    Token ledgers. Only the Super Admin can record
  /stripe_credits,        grants, credited Stripe payments and fund changes.
  /token_donations,
  /token_redistributions
  /lms_courses            Teachers can edit only their own courses. Courses
                          created before ownership was recorded can be
                          claimed by the first teacher who saves them.
  /users                  New: nobody can raise their own token balance or
                          give themselves a Charity Pass (both were possible
                          before). Spending tokens still works. The verified
                          project-owner account is treated as Super Admin.

!! BEFORE DEPLOYING — chat_interactions is shared !!
  The Firebase project already had a chat_interactions collection. If another
  app writes to it, its rules exist only in the Firebase Console (they are not
  in this file) and deploying would replace them. Do section 4, Step 3
  (back up the live rules) and copy any chat_interactions rules for the other
  app into firestore.rules first. The OzEdu rules only allow documents with
  kind == 'lms_message', so they will not expose the other app's data.

Test the rules before deploying (needs Java 11+ for the emulator):
    npm run test:rules
    npm run test:e2e
  Java: install "Temurin 21 JRE" from adoptium.net if "java -version" fails.
  Both commands use local emulators only (project ids demo-...), no login.
